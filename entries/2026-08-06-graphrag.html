GraphRAG — should I invest in it?

2026-08-06

Follow-up note to today's pipeline entry: PDF extraction → chunking → embedding is working, and the open question is whether to keep exploring different RAG techniques such as GraphRAG.

Why GraphRAG is on the table

  • The current setup is a plain vector RAG: chunks are retrieved by embedding similarity.
  • Vector RAG struggles with questions that need multi-hop reasoning across documents, e.g. "which standards mention both 재료 and 강도?".
  • GraphRAG builds a knowledge graph of entities and relations and retrieves over it, which can answer those questions — but it costs more to build and maintain.

Quick check before committing

  1. Do the research questions actually require relationships between entities?
  2. Is the corpus small enough that entity extraction is tractable?
  3. Will the ontology work (표준어휘 2025-2) feed the graph anyway?

Decision rule

Run a small GraphRAG pilot only if the answer to (1) is yes. Otherwise improve chunking and retrieval quality on the current vector pipeline first.
